# audit_lexicon.py 는 무슨 일을 하나요?

아주 짧게 말하면: **우리가 만든 단어장을, 똑똑한 AI에게 "이거 맞게 만든 거 맞아?" 하고 채점받는 프로그램**입니다.

---

## 1. 먼저, 단어장이 뭔가요?

병원에서 가슴 엑스레이를 찍으면 의사 선생님이 소견서를 씁니다.
"오른쪽 폐에 물이 조금 찼습니다" 같은 글이죠.

우리는 이런 글을 컴퓨터가 읽고, 나오는 단어들을 하나하나 뽑아서 모아 두었습니다.
그 모아 둔 결과가 `out/lexicon/lexicon.tsv` 파일이고, 줄이 **4만 8천 줄**쯤 됩니다.

한 줄은 이렇게 생겼습니다.

```
entity   pleural_effusion   160473   A   exact   RID34539   pleural effusion   ...
```

읽는 법:

| 칸 | 뜻 | 예시 |
|---|---|---|
| field | 이 단어가 **어떤 종류**인가 | 아래 표 참고 |
| label | 단어의 대표 이름 | `pleural_effusion` (흉수, 가슴에 물참) |
| n | 소견서에 **몇 번 나왔나** | 160473번 |
| grade | 우리가 매긴 **등급** | A |
| rid | 세계 공용 의학 사전에서의 **번호** | RID34539 |
| variants | 실제로 글에 쓰여 있던 **여러 표현** | "pleural effusion", "effusions", "fluid" ... |

`field` 는 딱 세 종류로 나눠 놨습니다.

- **anatomy(몸의 부위)** — 폐, 갈비뼈, 심장처럼 **몸의 어디**
- **entity(발견된 것)** — 폐렴, 골절, 관(튜브)처럼 **무엇이 있다**
- **descriptor(설명하는 말)** — 약간, 심한, 좋아짐처럼 **어떤 상태다**

## 2. 등급 A·B·C·D 는 어떻게 매겼나요?

세상에는 **RadLex**라는 아주 큰 의학 단어 사전이 있습니다. 우리 단어를 이 사전에서 찾아본 겁니다.

- **A** — 사전에 **그대로 있다**. 좋아요.
- **B** — 사전에 있긴 한데, 우리가 **군더더기를 붙였다**. (사전엔 "갈비뼈", 우리는 "오른쪽 세 번째 갈비뼈")
- **C** — 사전에 **없는데 자주 나온다**. 우리끼리 뜻을 정해야 합니다.
- **D** — 사전에도 없고 **거의 안 나온다**. 그냥 둡니다.

**여기에 큰 문제가 하나 있습니다.**
이 등급을 매긴 프로그램은 **글자만 비교**했습니다. 뜻은 하나도 모릅니다.
사람으로 치면, 영어를 전혀 모르는 사람이 사전에서 **똑같은 글자가 있나만** 확인한 것과 같아요.

그래서 이런 실수를 못 잡습니다.

> 🍎 **"배"** 라는 단어를 사전에서 찾았더니 "물 위에 뜨는 배"가 나왔습니다.
> 글자는 똑같으니 프로그램은 "맞았다! A등급!" 합니다.
> 하지만 우리가 말한 건 **사람 몸의 배**였죠. 완전히 틀렸습니다.

`audit_lexicon.py` 는 **바로 이런, 글자로는 못 잡는 실수를 찾는 프로그램**입니다.

## 3. AI에게 무엇을 물어보나요?

AI에게 4만 8천 줄을 그냥 던져 주고 "잘 봐 줘"라고 하면 안 됩니다.
아무 말이나 잔뜩 해 버리거든요. 그래서 **질문을 아주 좁게** 만들었습니다.

AI에게 이렇게 설명해 줍니다.

1. 이건 가슴 엑스레이 소견서에서 뽑은 단어장이다.
2. field 세 종류의 뜻은 이렇다. (몸의 부위 / 발견된 것 / 설명하는 말)
3. 등급 A·B·C·D는 **글자만 비교해서** 매긴 거다. 뜻은 아무도 안 봤다.
4. **그러니 네가 볼 것은 "글자"가 아니라 "뜻"이다.**

그리고 딱 5가지만 봐 달라고 합니다.

- ① 사전 번호(RID)가 **정말 같은 뜻**인가? (위의 "배" 문제)
- ② field가 **맞는 칸**에 들어가 있나? (혈관 이름이 "설명하는 말" 칸에 있으면 틀린 것)
- ③ variants(실제 표현들)가 **전부 같은 뜻**인가? 하나라도 다른 게 섞였나?
- ④ 군더더기가 붙었거나(`overspecified`), 반대로 **중요한 걸 빠뜨렸나**(`underspecified`)?
- ⑤ 같이 보여 준 다른 줄과 **사실 같은 말**인가?

또 **하지 말 것**도 분명히 말해 둡니다.

> "드물게 나온다고 해서, 사전에 없다고 해서 틀린 게 아니다. 그건 원래 그런 거다."
> "새 단어 체계를 지어내지 마라."
> "괜찮은 줄이면 그냥 '괜찮다'고만 말해라. 대부분은 괜찮다."

이걸 안 써 두면 AI가 멀쩡한 줄까지 전부 트집 잡습니다.

## 4. 중요한 장치: 사전을 직접 보여 줍니다

AI에게 `RID34539` 라는 **번호만** 주면, AI는 그 번호가 뭔지 모르면서 아는 척을 합니다.
(이걸 '환각'이라고 불러요. 모르면서 지어내는 것.)

그래서 프로그램이 미리 RadLex 사전을 열어서, **그 번호의 진짜 이름과 뜻풀이를 찾아 붙여** 줍니다.

```
row_id: descriptor|left_brachiocephalic_vein
  field: descriptor   label: left_brachiocephalic_vein
  grade: B
  radlex: RID1011  brachiocephalic vein        ← 진짜 이름을 붙여 줌
  radlex_definition: 목 아래쪽의 큰 정맥 ...    ← 뜻풀이도 붙여 줌
  variants: "likely in the left brachiocephalic vein":1
```

이러면 AI는 **찾아볼 필요 없이 바로 판단**할 수 있습니다.
실제로 위 줄은 **혈관(= 몸의 부위)인데 "설명하는 말" 칸에 잘못 들어가 있는** 진짜 오류입니다.

## 5. 대답은 정해진 말로만 받습니다

AI가 긴 감상문을 쓰면 4만 8천 줄을 정리할 수가 없습니다.
그래서 **객관식처럼** 답하게 만들었습니다. 고를 수 있는 답은 이 8개뿐입니다.

| 답 | 뜻 |
|---|---|
| `ok` | 이 줄은 괜찮다 |
| `wrong_rid` | 사전 번호가 딴 뜻이다 (= "배" 문제) |
| `wrong_field` | 칸을 잘못 골랐다 |
| `overspecified` | 군더더기가 붙었다 |
| `underspecified` | 중요한 뜻을 빠뜨렸다 |
| `mixed_variants` | 서로 다른 게 한 줄에 섞였다 |
| `not_a_concept` | 단어가 아니다, 그냥 문장 조각이다 |
| `duplicate` | 다른 줄과 똑같은 말이다 |

여기에 **얼마나 확신하는지**(high/medium/low), **고치면 뭐가 되는지**, **왜 그렇게 봤는지 한 줄** 을 같이 받습니다.
답의 모양을 컴퓨터가 강제하기 때문에(`json_schema`), AI가 엉뚱한 형식으로 답할 수 없습니다.

## 6. 4만 8천 줄을 다 물어보지는 않습니다

한 번에 25줄씩 묶어서 물어봅니다. 전부 다 하려면 **2천 번쯤** 물어봐야 하고, 돈이 듭니다.

그래서 기본은 **골고루 뽑아서** 물어봅니다. 뽑는 방법이 조금 영리합니다.

- 그냥 아무거나 뽑으면, 4만 2천 줄이 D등급이라 **거의 D만 뽑힙니다.** D는 고쳐 봤자 별 소용이 없어요.
- 그래서 (field 3종류) × (등급 4종류) = 12칸으로 나눠서 **각 칸에서 공평하게** 뽑습니다.
- 각 칸에서도 **절반은 많이 나온 순서로**, 절반은 무작위로 뽑습니다.
  많이 나온 단어의 오류는 고치면 효과가 크고, 무작위 절반은 "상위권만 보다가 놓치는 것"을 막아 줍니다.

그리고 한 번 물어본 줄의 답은 파일에 **차곡차곡 저장**해 둡니다.
다음에 다시 돌리면 **이미 물어본 건 건너뜁니다.** 돈과 시간을 아끼려는 거예요.

## 7. 어떻게 실행하나요?

```bash
export OPENAI_API_KEY=...                              # 열쇠 등록

python3 GPT/audit_lexicon.py --sample 40 --dry-run     # 연습: 질문지만 보고 끝
python3 GPT/audit_lexicon.py --sample 400              # 400줄 채점 (25번쯤 물어봄)
python3 GPT/audit_lexicon.py --grade A --min-n 50      # 자주 나오는 A등급만 전부
```

`--dry-run` 은 **AI를 부르지 않고 질문지만 보여 줍니다.** 돈이 한 푼도 안 듭니다.
질문이 이상하지 않은지 먼저 눈으로 확인하는 용도예요. 항상 이것부터 해 보세요.

결과는 `out/gpt_audit/` 안에 나옵니다.

- `audit.md` — 사람이 읽는 **성적표**. 어떤 오류가 몇 개인지, 그중 **자주 쓰이는 단어부터** 60개.
- `audit.tsv` — 표 프로그램으로 열어서 정렬하고 걸러 볼 수 있는 **전체 목록**.
- `verdicts.jsonl` — 물어본 기록 창고. 다시 돌릴 때 건너뛰기용.

## 8. 한 장 요약

| | |
|---|---|
| **왜 만들었나** | 등급을 매긴 프로그램이 글자만 봐서, **뜻이 틀린 걸 못 잡기** 때문 |
| **누가 채점하나** | 외부 AI (모델 이름은 `--model` 로 바꿀 수 있음) |
| **무엇을 묻나** | 사전 번호 / 칸 / 표현들이 같은 뜻인지 / 군더더기 / 중복, 이 5가지만 |
| **헛소리 막는 법** | 사전 뜻풀이를 직접 붙여 주고, 답은 8개 중 객관식으로만 받음 |
| **돈 아끼는 법** | 골고루 뽑아서 일부만, 한 번 물어본 건 저장해 두고 건너뜀 |
| **결과** | `out/gpt_audit/audit.md` (성적표), `audit.tsv` (전체 목록) |

⚠️ 마지막으로 하나. **AI의 채점도 100% 정답은 아닙니다.**
이 프로그램이 주는 건 "여기 좀 이상해 보여요" 하는 **사람이 확인할 목록**이지,
이대로 자동으로 고쳐 버리는 물건이 아닙니다. 고칠지 말지는 사람이 정합니다.
